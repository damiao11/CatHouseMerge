# 08 · 范围与风险

> 两人做、24 天内容、约 61 个美术资源。这一章只定"做什么、不做什么、做不完怎么办"，**不排工期**。

## 8.1 MVP（必须做完）

- [ ] 7×9 棋盘 + 拖拽合成（同链同级）
- [ ] 7 条链、39 个物品的数据
- [ ] **生成器升级**（7 个、两个同级合成、等级继承、按章限级、**各占棋盘 1 格**）
- [ ] **仓库**（6 格免费，金币扩容至 12，收纳物品与生成器）
- [ ] 订单系统（每日固定 4–6 条、全部显示、交付、金币）
- [ ] 建造系统（金币 + 成品，每房 3 步）
- [ ] 24 天推进 + 8 间房揭幕
- [ ] 体力（150 / 2 分钟）+ 恢复结算
- [ ] 存档（杀进程能恢复）
- [ ] 对话系统（头像 + 打字机 + 点击继续）
- [ ] 三套界面：棋盘 / 建造 / 对话
- [ ] 一套统一的图标（可以用简化版）

## 8.2 加分项（按性价比排序）

| 优先级 | 功能 | 相对成本 | 收益 |
|---|---|---|---|
| 1 | Debug 面板 | 小 | 调难度、答辩加分 |
| 2 | 猫图鉴 | 小 | 收集感、UI 展示点多 |
| 3 | 音效 + BGM | 小 | 手感提升巨大 |
| 4 | 建造前后对比动效 | 中 | "哇"的一下 |
| 5 | 每日结算页 | 小 | 节奏感 |
| 6 | 仓库 | 中 | 降低挫败 |
| 7 | 减少动态效果开关 | 小 | 无障碍加分 |

## 8.3 明确不做

- 排行榜、云存档、账号
- 内购、广告、分享
- 多语言
- 横屏 / 平板
- 食物 / 烹饪系统
- 多结局分支树
- 3D、粒子系统、着色器
- 随机订单（订单全部手写，每天固定）

## 8.4 两人怎么分（建议，不是排期）

| 人 | 负责 | 产出 |
|---|---|---|
| A（系统） | 棋盘、合成、订单、建造、存档、体力、Debug 面板 | 可玩的无美术闭环 |
| B（内容与表现） | UI 规范、界面、动效、图标、房间图、剧情文本 | 视觉与叙事 |

**接口约定**：A 先把 7 条链和 24 天的数据结构（JSON schema）定下来，B 按 schema 填内容。**数据结构先于美术**，否则 B 画完了 A 接不上。

## 8.5 做不完怎么办（降级预案）

| 版本 | 内容 | 触发条件 |
|---|---|---|
| 完整版 | 24 天 / 8 房 / 7 链 | 目标 |
| 标准版 | **18 天 / 6 房 / 6 链**（砍第四章前两间） | 内容进度落后 |
| 最小版 | **12 天 / 4 房 / 4 链**（门廊、客厅、卧室、厨房） | 只剩一半时间 |

**降级原则**：**先砍天数，不砍房间的完成度**。宁可 12 天每间房都精修，也不要 24 天每间房都半成品——老师看的是 UI 质量，不是关卡数量。

## 8.6 风险矩阵

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **61 个图标做不完 / 不统一** | 高 | 高 | 先定风格；先做 7 条链的 1、3、5 级，中间级后补 |
| 拖拽手感差 | 中 | 高 | 第一个可玩版本就做手感，找 3 个人试 |
| 数值失衡（太肝 / 太松） | 高 | 中 | 全表驱动 + Debug 面板 + 每章试玩 |
| 24 天内容录入枯燥出错 | 中 | 中 | JSON schema + 校验脚本（检查每天结余为正） |
| 8 张房间前后图太贵 | 中 | 高 | 用"局部前后对比"代替整间重画 |
| 存档丢档 | 低 | 高 | 原子写 + 备份 + 版本号 |
| 剧情写不出来 | 中 | 低 | 只写 3000 字，第一版已完成（见 14） |
| 答辩演示翻车 | 中 | 高 | 提前录屏 + Debug 面板 |

## 8.8 五分钟演示脚本

| 时间 | 内容 | 讲什么 |
|---|---|---|
| 0:00–0:30 | 一句话 + 参考作品 | "合成 + 建造 + 猫" |
| 0:30–1:30 | 现场玩 D1 | 合成手感、音效、动效 |
| 1:30–2:30 | 跳到 D12 | 建造揭幕、通电那一刻 |
| 2:30–3:30 | 打开 24 天难度曲线 | 三次呼吸 + 一次剧情关 |
| 3:30–4:30 | Debug 面板改一个数 | 现场演示"难度可调" |
| 4:30–5:00 | 结局 + 图鉴 | 收尾情感 |

> **一定要现场改一个数值**。这是"难度控制"最有力的证明。
